## 2. Архитектура модели и потоки

### Многопоточности в проекте
В основе программы лежит использование потоков стандарта POSIX. 
* **Общая память и изоляция:** Все потоки внутри одного процесса делят общее виртуальное адресное пространство. Глобальные переменные, куча (heap) и сегменты кода у них общие. Индивидуальными для каждого потока остаются только стек (stack) для локальных переменных и архитектурное состояние (регистры и счетчик команд). Благодаря общей памяти, потоки садовников в программе могут напрямую обращаться к массиву цветов `garden->flowers`.
* **Жизненный цикл и планировщик:** При вызове `pthread_create` ядро ОС выделяет для нового потока стек и добавляет его в очередь готовых задач. Планировщик квантует время процессора, регулярно переключая контекст между главным потоком и потоками садовников, обеспечивая параллельное выполнение.
* **Проблема Race Condition:** Из-за общей памяти одновременный неконтролируемый доступ к одним и тем же данным (например, попытка двух садовников полить один цветок) приводит к ошибкам. Это требует строгой синхронизации.

### Распределение ролей в программе
В разработанной программе моделируемые сущности и их поведение распределены между основным и рабочими потоками:
* **Сад (Клумба с цветами):** Управляется в главном потоке (`main`). Главный поток инициализирует систему, в цикле с заданным шагом времени (`dt`) вызывает функцию `garden_tick`, которая обновляет состояние всех цветов (уменьшает влажность, меняет состояния: `NORMAL` -> `WILTING` -> `DRYED`), и следит за условиями окончания симуляции.
* **Садовники:** Реализованы в виде отдельных рабочих потоков (функция `gardener_thread`). Каждый садовник непрерывно проверяет сад на наличие увядающих цветов (`FLOWER_WILTING`). Если такой цветок найден, садовник "закрепляется" за ним и осуществляет полив.

### Синхронизация взаимодействия
Для предотвращения гонок данных потоки асинхронно взаимодействуют с общим ресурсом (структурой `Garden`) с использованием синхропримитивов:

1. **Мьютексы (`pthread_mutex_t`):** Работают как эксклюзивный замок. Вызов `pthread_mutex_lock(&garden->lock)` гарантирует, что только один поток находится в критической секции кода. Если второй поток попытается выполнить `lock`, планировщик ОС усыпит его, не тратя процессорное время, пока первый поток не вызовет `unlock`. Дополнительный мьютекс `log_lock` используется для синхронизации вывода в консоль, чтобы строки логов не перемешивались.

2. **Условные переменные (`pthread_cond_t`):** В качестве дополнительного требования (вместо базовых семафоров) применена условная переменная `garden->changed`, решающая проблему ожидания событий. Если садовник видит, что поливать нечего, он не крутится в бесконечном цикле (busy-wait), а вызывает `pthread_cond_wait`. ОС атомарно отпускает мьютекс и усыпляет поток. Когда `garden_tick` обнаруживает, что цветок начал увядать, он вызывает `pthread_cond_broadcast`, и ОС мгновенно будит спящих садовников.

## 3. Пользовательский интерфейс

Программа представляет собой консольное приложение для ОС Linux (CLI).
Взаимодействие с пользователем реализовано на этапе запуска: программа предлагает интерактивно задать параметры симуляции (количество цветов, скорости высыхания, объемы полива, время задержки и т.д.). Для защиты от некорректного ввода используются безопасные функции на основе `fgets` и `strtol`/`strtod` с обработкой ошибок.

В процессе работы вывод осуществляется в формате журнала событий (лога), где каждая строка предваряется текущим временем симуляции. Задержки `usleep` обеспечивают наглядное и плавное отображение процесса.

## 4. Запуск и условия завершения

**Запуск:**
Программа компилируется с флагом `-pthread` и запускается из терминала. Сразу после запуска пользователю предлагается ввести параметры или использовать значения по умолчанию, нажав Enter.

**Условия завершения:**
Программа может завершиться по трем сценариям:

1. **Штатное завершение по времени:** Текущее время симуляции превысило заданное в настройках (`config.duration`).
2. **Гибель всех цветов:** Значение `alive_count` стало равным нулю.
3. **Принудительное прерывание (Сигналы):** В программе реализован обработчик сигнала `SIGINT` (перехват `Ctrl+C`). При получении сигнала устанавливается глобальный флаг `g_stop = 1`. Потоки замечают этот флаг, корректно снимают блокировки, завершают свою работу, после чего программа выводит итоговую статистику и безопасно освобождает память.

## 5. Дополнительные требования (Бонусные баллы)

В ходе разработки были реализованы следующие дополнительные функции:
* **Обработка сигналов:** Корректное прерывание работы через `SIGINT` с безопасным завершением потоков (`pthread_join`).
* **Сбор и вывод статистики:** По завершении симуляции программа рассчитывает и выводит на экран итоговую таблицу состояний всех объектов.
* **Интерактивная конфигурация с валидацией:** Безопасный ввод параметров с защитой от некорректных типов данных.
